Linear lessons we can apply without copying Linear

Linear's public site and product positioning repeatedly emphasize purpose-built workflows, speed, reduced noise, momentum, and craft. Blocks already has a strong functional core; the opportunity is to make it feel calmer, sharper, faster, and more intentional.

Linear principle: focus

Reduce visual noise and expose controls only when contextually needed.

Linear principle: speed

Keyboard-first flows, instant command access, fewer modal interruptions.

Linear principle: craft

Precise spacing, subdued colour, crisp surfaces, high-quality micro-interactions.

Suggested visual direction

Do not make Blocks dark or purple just because Linear is sleek. Blocks is a planning canvas, so keep it light and quiet. Borrow Linear's restraint: low-contrast chrome, sharp typography, fewer competing borders, and colour used for information rather than decoration.

Concrete CSS/UI changes worth doing first

  • Reduce border density: replace many 1px grid/header outlines with softer rgba(0,0,0,.06) and section backgrounds.
  • Normalize radius scale: use 4px for dense controls, 8px for menus/popovers, 12–14px for panels; avoid mixed 2/4/5/6/8/12 unless intentional.
  • Make context menus feel premium: slightly darker text, 10–12px radius, box-shadow: 0 12px 40px rgba(0,0,0,.14), tiny scale/fade in.
  • Improve timeline header hierarchy: month row bolder/darker, week/day rows smaller/subtler; milestone lane as a calm neutral band.
  • Unify controls: inputs in map and data should share focus ring, hover border, and padding.
  • Use accent sparingly: one accent colour for active/selected/focus, not for every decorative element.

Product/workflow changes inspired by Linear

⌘K command palette

Best single Linear-style improvement. Speeds up experienced users and reduces visible UI clutter.

Selected item actions

Click block/milestone to select; actions become keyboard/context-menu driven rather than always visible.

Project health/status strip

Show save state, project date range, block count, milestone count, last edited — minimal, status-oriented.

Updates/change log panel

Linear uses updates to create momentum; Blocks could show recent changes or last 10 edits.

Smart defaults

When creating blocks, keep recent track/resource/duration/tag colour defaults to reduce repetitive setup.

Keyboard shortcuts help

A small ? overlay: create, rename, delete, move, resize, jump today, zoom, collapse.

Recommended implementation order

  1. Polish pass: neutral palette, border/radius scale, context menu styling, timeline header hierarchy.
  2. Command menu: start with 8–10 commands, no AI/features bloat.
  3. Keyboard selection model: selected block/milestone, rename/delete/move/resize shortcuts.
  4. Status strip + recent activity: make progress and sync feel more intentional.

Bottom line

Yes — Blocks can benefit a lot from Linear's lessons. The best transfer is not the exact look; it's the discipline: reduce noise, optimize for speed, make every interaction feel intentional, and hide complexity until it is needed. Blocks should stay a precise timeline/planning tool, but with Linear-like calmness and keyboard momentum.
